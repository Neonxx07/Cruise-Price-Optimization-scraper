navigated to a **relative** URL (`/espresso/...`), which `page.goto()`
rejects. It threw on **every** attempt — 21 of 22 `booking_release_failed`

A 2026‑08‑13 audit had recorded that behaviour as "CONFIRMED INTENTIONAL
DESIGN" and written a test to lock it in. **A test defending a behaviour is
not evidence the behaviour is correct.**

**Prices thrown away.** Two sentinel paths returned no figures at all while

### We were under-quoting, and the reason was in our own note

Booking 3001021: we quoted $2,231 → $2,183 (save **$48**); Neon's ledger
showed he achieved $2,117 (save **$114**) — $66 better, unexplained.

Next day he questioned 3001023 and 3001022, whose scans said OPTIMIZATION
while the portal's Rate Comparison appeared to show a HIGHER price. The
screenshots turned out to be a different rate selection — his own
correction — but chasing it produced the second data point: we quoted
$2,547, the portal showed **$2,481**. **$66 again.**

Both gaps are exactly the value of `Email Bonus NRD` — **the promo the note
was already telling him to re-add**:

```
optimized $48 — re-add: Email Bonus NRD
```

The calculator identified the promo correctly and left its money out of the
figure, so every quote carrying a re-addable fare read low.

| booking | we quoted | with it re-added | actual |
|---|---|---|---|
| 3001021 | $48 | **$114** | **$114** |
| 3001022 | $50 | **$116** | **$116** |

**Measured: 401 bookings carry a re-addable promo with a real dollar value,
totalling $97,565** absent from quoted savings — Email Bonus NRD (234),
BONUS SAV NRD (91), WEEKENDSAV NRD (42).

The note now states the ceiling:

```
optimized $50 — re-add: Email Bonus NRD
              (worth $66.00 — saving becomes $116.00 if re-added)
```

**`net_saving` is deliberately NOT inflated by it.** Re-adding is a manual
step on the Promotions screen and it can fail; promising unsecured money is
the OBC mistake reversed. A re-addable promo can never flip a verdict. Where
no priced `CRUISE_PROMO` line exists, the note names the fare and stops
rather than inventing a value.

## METHOD

Every fix that stuck came from **measuring the log or the database**, not
from reading code and guessing. **Comments in this codebase have lied at
least six times**, each describing an intention the code contradicted.

Test anti-patterns that have bitten repeatedly:

- **matching prose instead of code** — strip comments via AST;
- **character-distance windows** (`assert X in src[i:i+400]`);
- **pinning "the newest capture"** — an exact-figures test broke the moment a
  new scan landed. Pin the capture DAY when pinning numbers; use the newest
  only for invariants;
- **budget-based guards** — a commission test allowed "at most 2 references",
  and the budget was already spent by two unrelated names, so a new one would
  have slipped through. Allowlist by name.

And: **a status code is evidence; a URL that failed to change is not.**
