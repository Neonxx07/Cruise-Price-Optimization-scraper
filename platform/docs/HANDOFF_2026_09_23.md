## WHAT WAS FIXED — verify these still hold

### 1. ESPRESSO bookings were left LOCKED (the V-VIP one)

ESPRESSO holds a **15-minute lock** on any retrieved reservation. Measured:

```
bookings opened : 624
  released      : 235
  LEFT LOCKED   : 389    (62%)
release events  : 293 released, 1 skipped, 0 FAILED
```

The release mechanism was never broken — it just wasn't *called*.
`release_booking` had ONE call site on the happy path while the flow had
**15 returns and 6 raises**; 19 of 20 exits skipped it. The comment above
that call claimed it ran "for every branch above". It did not.

**Fix:** `check_booking` is now a thin wrapper with the release in a
`finally`, delegating to `_check_booking_inner`. Idempotent via
`_released_for` (set only on a CONFIRMED release; an unconfirmed one is
retried). `_ensure_released` never raises.

Guard: `tests/test_espresso_release_always_2026_09_23.py` (15 tests),
including a structural test asserting the release is in the `finally`.

**NEVER move the release back onto a branch.**

### 2. "Logged out mid-scan" was mostly a self-inflicted race

All three "logouts" that day recovered on their own in seconds; the scan
never stopped. What Neon sees is the login page *flashing*.

`navigate()` waits for `domcontentloaded`, which fires before /home finishes
its session bootstrap. The flow spent a median **136ms** there, then left —
and /home's in-flight redirect cancelled the next navigation:

```
navigate_retry : 271
net::ERR_ABORTED : 268   (all on reservations.do)

time on /home before leaving:
  aborted (270)  median  668ms   navigate_reservations 3130ms
  clean   (374)  median 1068ms   navigate_reservations 1015ms
```

**Fix:** `_settle_navigation()` polls `page.url` until stable, called after
`navigate(/home)` and **before** `_check_login` — which fixes both the
aborted navigation and the phantom logout (the login check was sampling a
half-built login form).

Guard: `tests/test_espresso_settle_navigation_2026_09_23.py` (7 tests).

### 3. Crashes never reached the log

`gui.main._handle_async_exception` did `print(...)` to stdout. A RuntimeError
killed an overnight 721-booking scan and appeared **4 times in stdout, 0
times in the log**, so the watchdog could not see it.

**Fix:** `utils/logging.py` gained `log_crash()`, `install_crash_handlers()`
(sys + threading excepthooks, chained) and `asyncio_exception_handler()`.
Event name: `crash.unhandled`, with full traceback.

### 4. GUI `_on_start` re-entrancy

A second Start click during the stale-code modal created a second task;
qasync then destroyed the running batch mid-scan. `_start_in_progress` flag
is now set **before any dialog**.

### 5. Watchdog was half-blind

`python scan_watchdog.py` (auto-finds the GUI process; `--pid` overrides).
Added: `m_crashes` (ALARM on first), `m_process` (process death),
`m_navigation_retries` (WARN 15% / ALARM 40%). Fixed: progress now means a
booking *starting* (`*.result` gapped 26.8 min on a healthy run and would
have raised 5 false stall alarms); cancellations now counted (they emit
`espresso.booking_cancelled`, never `*.result`, so `m_cancellations` could
never fire — 8 real cancellations went unreported).

## FIRST TASK — verify the two ESPRESSO fixes on a live run

Restart the GUI, run a batch, then check the log:

```bash
python - <<'EOF'
import json, pathlib, collections
recs=[json.loads(l) for l in pathlib.Path("data/cruiseintel.log")
      .read_text(encoding="utf-8",errors="replace").splitlines() if l.startswith("{")]
cur=[r for r in recs if r.get("timestamp","") >= "PUT_RUN_START_HERE"]
by=collections.defaultdict(set)
for r in cur:

esp={b:s for b,s in by.items() if any(x.startswith("espresso.") for x in s)}
rel={b for b,s in esp.items() if "espresso.booking_released" in s}
print(f"opened {len(esp)}  released {len(rel)}  LOCKED {len(esp)-len(rel)}")
ab=[r for r in cur if r.get("event")=="browser.navigate_retry"]
print(f"navigate_retry {len(ab)} of {sum(1 for r in cur if r.get('event')=='espresso.navigate_home')} navigations")
EOF
```

**Pass = LOCKED near 0, and navigate_retry well under 10%.**
Before the fixes: 389 locked, 42% retry rate.

## STILL OPEN

1. **Does ESPRESSO have an absolute session cap?** Not proven. That day's
   login-to-logout gaps were 1h35m / 3h37m / 4h03m — no clean period, and all
   recovered, so evidence points at the race. If logouts persist after the
   fix, test this next and collect the log.
2. **`release_booking` costs a median 9.2s — 46.7% of scan time.** Now that
   the 389 previously-leaking bookings actually release, a 721-booking run
   gains roughly an hour. This is the highest-value speed target left.
3. **Timings exist only on ESPRESSO** (and only ~19% of bookings). NCL, GoCCL
   and MSC emit none — a delay there is invisible.
4. **Emit a `<line>.result` on every terminal path.** One fix closes both the
   19% timing coverage and `m_status_mix`'s 16% blindness (PAID_IN_FULL and
   WLT have no distinguishing event).
5. **Nothing notifies Neon.** Every path ends in text on a screen. Researched:
   Apprise (`windows://`, no API key, needs pywin32) for local toast, phone
   variant for overnight runs; py-spy for dumping a hung process. None
   installed.
6. **`_check_login` trusts a stale DOM after a failed navigation** — reported
   `ALREADY_LOGGED_IN` while sitting on `/login`.
7. **MSC:** `msc_discount_beats_current` / `best_eligible_discount` /
   `purchased_extras_total` are built and tested but **not wired** into
   `DISCOUNT_ADD` / `VOYAGERS_SELECTION`. MSC writes JSONL only, nothing to DB.
8. **GoCCL `/review`** not wired into production `check_booking`.
9. Re-scan the 82 non-USD ESPRESSO optimizations (~$16,000) and the 27
   suspected-cancelled bookings in `data/suspected_cancelled.txt`.

## METHOD THAT WORKED — keep using it

Every fix above came from **measuring the real log**, not from reading code
and guessing. Three separate comments in this codebase confidently described
behaviour the code did not have, and each one hid a real bug for months.
Verify claims against `data/cruiseintel.log` and `cruise_intel.db` before
trusting them — including comments, docstrings, and test docstrings.
